# Remaining implementation work

The first public version covers the implemented local sequencing, arrangement, editing and export workflows. Keep the app runnable and preserve source, media and recovery copies. The full reference inventory remains a roadmap. Use CONTRIBUTING.md for contribution priorities and PARITY.md for exact coverage. Publishing a version does not establish hardware or third-party compatibility.

1. Finish arrangement automation clips, complete piano tools, independent channel loops. Named, seekable history is implemented. Native audio clips, phase-preserving cuts, compatible joins, groups, mutes, trim-to-cursor and clip clipboard now work; guarded pattern splitting refuses held-note cuts. Shared multichannel patterns, compact checked note channel/source IDs, independent playlist rows/mutes, right-edge resize, arrangement pan/zoom/scroll, rectangle selection and ghost notes are implemented. Legacy arranged audio is preserved in migration tests; full reference semantics still need acceptance.
2. Finish live graph exchange and audition and CoreMIDI recording/controllers/sync. Playback now uses an owned bounded SPSC queue, a distinct long-song compiler and a worker; edits still stop it. Preserve the zero-allocation processing and queue tests and measure physical latency/dropouts instead of inferring them from an offline benchmark.
3. Finish recording device/permission acceptance, count-in, transport alignment, file-backed long sessions and power-loss/stress acceptance. Common CPAL capture now writes a selected pair or all 1–32 input channels through bounded SPSC queues and one disk worker. Original float32 WAV takes remain on disk, headers checkpoint roughly once per second per input pair, and explicit recovery repairs only the in-memory view. Multiple takes insert as one undo step; failed insertion retains every pending sample. The project still caps aggregate embedded samples at four million frames and capture at 120 seconds; the real capacity depends on rate, active pairs and samples already present. Tests use synthetic callbacks and owned temporary files, never the microphone.
4. Finish lawful FLP version/playlist/mixer/automation/plugin interpretation and full writer support. Two pinned public real-file fixtures now import and round-trip byte exactly without edits. This does not establish FL Studio application acceptance, musical equivalence or support for their original plugin/arrangement data. Do not weaken unsupported-edit refusal or alter trial/license fields. The selected-arrangement reader now supports validated uncropped pattern records from FL 12.9.1–20, with original positions/durations/rows/groups and row mutes. Other formats/flags/crops/audio/automation remain opaque and reported; this is partial FLP support.
5. Replace/strengthen native plugin isolation for arbitrary binaries; hard memory quotas fail on the tested Mac. Retain fail-closed behavior. The common host now implements exact included-module path/hash checks, native loaders and per-OS limits on all three systems. The public offline diagnostic writes new reports without overwriting earlier ones. These controls admit only our packaged plugin; Windows/Linux execution remains pending. Complete live slots, state/preset storage, editor/automation support, external CLAP host acceptance and VST3 implementation. VST3 3.8 MIT licensing is verified; VST2 remains a separate legal/API task.
6. Finish instrument parameter editors, effects, sidechains/delay compensation, all automation targets and professional listening validation. Existing granular stretch is experimental. FLAC MD5 read/write is now implemented and checked against published vectors, an RFC decoding example and Apple's PCM output. AIFF/AIFF-C import, AIFF PCM export and aligned active-channel stems with sends are implemented. AIFF and integer/float AIFF-C were cross-checked against Apple conversion for the owned fixture. More corpora, seeking/metadata, disk-streamed long export and MP3/Vorbis remain pending.
7. Finish recovery archive management, persistent panel layouts and full canvas accessibility. Persistent theme/audio/ghost-note choices and recent files are implemented with bounded checked preferences. Corrupted configuration is retained and never silently overwritten. The approved logo/moodboard are fixed; dark is the default and light requires explicit selection. Strict Windows gnullvm and Linux GNU cross-target checks now cover core/plugins/GUI. Complete Windows and Linux applications cross-link and are packaged as internal test archives; native runtime acceptance and final installation/signing/distribution remain pending. The owner will provide both system results. Offline test suites are cross-compiled separately under dist/qa; they have not run on those systems. Recovery retains eight copies / 128 MiB and pauses when full; never prune earlier music snapshots. File/directory sync semantics and actual power-loss behavior need acceptance.
8. Before each release: review current advisories, provenance/licenses, name/trademarks, external contributions, app integrity, Developer ID/notarization, clean-machine behavior and the behavior claimed for that version. Remaining reference work stays in the contribution roadmap.

Useful commands: `pnpm run check`, `pnpm run bundle`, `pnpm run check:plugins`, `pnpm run check:audio`, `pnpm run bench`, `pnpm run audit`. The plugin smoke test needs the current packaged app and matching signed first-party manifest. The FLAC smoke test needs the current release CLI and Apple's system audio tools. Both are offline and silent.

# First release: macOS, Windows and Linux

The owner confirmed on 2026-10-28 that all three applications are required in the first release. A Mac-only release does not satisfy that condition.

`apps/desktop` is the common Rust application. The same owned canvas, editor gestures, project commands and DSP are used on all three systems. Eframe/WGPU provide window/rendering integration; CPAL supplies CoreAudio, WASAPI and ALSA adapters. Rfd uses native file dialogs or the Linux desktop portal. These are architectural capabilities of the dependencies, not evidence that this application has passed runtime acceptance on every platform.

| Platform | Local evidence | Remaining acceptance |
|---|---|---|
| macOS Apple Silicon | Common UI compiles; strict Clippy, silent callback and headless editor tests; actual optimized bundle opens, instrument insertion/note editing/arrangement/save-copy and byte-exact WAV export exercised; real silent output probe and 14 own CLAP worker checks | Recording permission/device/unplug behavior, third-party plugin limits, clean machine, signing/notarization |
| Windows x64 | Strict cross-target Clippy for core, plugins and common GUI at `x86_64-pc-windows-gnullvm`; the complete x64 application/core/plugin cross-link, with PE import/ASLR/NX inspection; a readback-verified ZIP archive is staged | Real Windows execution, WASAPI/device/permission behavior, display scaling and file dialogs, executable icon/signing, first-party host acceptance, general third-party isolation and user installation |
| Linux x64 | Strict cross-target Clippy for core, plugins and common GUI; complete GUI/core/plugin cross-build with an official Ubuntu development sysroot and ELF dependency/NX/PIE/RELRO inspection | Actual Linux execution, ALSA/PipeWire routing and hot-plug, X11/Wayland/display portals, desktop entry/package, dependency maintenance, first-party host acceptance and general third-party isolation |

The CLAP adapter is shared as a separate owned crate. All three systems require the exact packaged first-party plugin path and matching SHA256 manifest before loading. Windows has a native loader and process-job limits; Linux uses dlopen, rlimits and no_new_privs. These are resource controls for included code, not general third-party filesystem/network sandboxes. macOS retains its default-deny sandbox and cannot enforce its requested memory limits. Every platform rejects external modules. Own built-in DSP works independently of hosted plugins. The linked Linux/Windows outputs are cross-build evidence; no Linux/Windows runtime pass is claimed from the Mac build.

The original native AppKit app remains available as local reference/fallback while the common app is checked. `pnpm run desktop:build` builds the optimized common binary; `pnpm run desktop:bundle` stages an internal preview under `dist/desktop/<platform>-<architecture>/`. This does not install files, register plugins or upload an artifact. The bundle carries a publication-gate record. Complete the missing behavior and actual supported-platform tests before producing a release.


## Local cross-link work, 2026-10-29

`pnpm run desktop:build:windows` uses the pinned official Zig 0.17.0 SDK and Rust's `x86_64-pc-windows-gnullvm` standard library. It is an experimental cross build, separate from native Windows/MSVC CI. The adapter supplies the CRT through Zig's UCRT libc selection and passes module definition files in the form its driver accepts. The complete official compiler runtime supplies the combined trigonometric and long-double operations expected by LLVM. The temporary DSP workaround was removed; the audio engine keeps its normal Rust math calls. No placeholder or approximate replacement was introduced. The complete GUI, core CLI and plugin now link. The x64 GUI executable SHA256 is `9b0fde6b05b54936f09f471cfec7f2718176d9905b65c8cd6ecada4b6530a708`. `outputs/windows-build-report.json` and `outputs/windows-pe-inspection.json` retain sizes/imports and distinguish linking from execution. The package is `dist/desktop/Garrido-Studio-Windows-x64-Preview-20261029.zip`, SHA256 `e41ad993dc49c3b3819b242be766f94f443649633dcd635251874f3a4628af71`. Its 717 entries were read back and checked against the staged files. Do not treat intermediate binaries as an application/runtime pass.

The newer Mac preview is staged separately at `dist/desktop/macos-arm64-preview-20261029/Garrido Studio.app`, preserving the earlier app and the ongoing session. Its packaged silent block-output probe and first-party plugin worker checks are bound to the executable hash in BUILD-EVIDENCE.md. Cross-built packages, when available, are internal testing artifacts until actual supported-system acceptance is recorded.


The complete Linux build succeeds at `x86_64-unknown-linux-gnu`, targeting glibc 2.39 (Ubuntu 24.04 baseline). The GUI executable is 20,678,616 bytes, SHA256 `c38c20a089acdb07eb84ef0029e0da930bb692c9f5af7a83de0aab1a460aa048`. ELF inspection finds NX, PIE and full RELRO, no runtime path into the Mac/sysroot, and direct requirements on ALSA, glibc, libm and the system loader. X11/Wayland/fontconfig/portal behavior still requires real desktop testing. The SDK was assembled from 11 official Ubuntu packages with SHA256 checks, including security-update ALSA 1.2.11-1ubuntu0.3; Debian maintainer scripts were not run. Official pkgconf 3.0.10 was built as a local tool to query actual metadata. Build tools/sysroot were not installed into macOS.

The common Mac suite can use `pnpm desktop:check --reuse --release` after its optimized dependencies exist, avoiding a duplicate debug cache when space is tight.
